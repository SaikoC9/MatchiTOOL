DECISIONS (ALL SIX ANSWERED AND CONFIRMED BY THE OWNER)
------------------------------------------------------------------
D1  Untracked trusted plugin (no approved record): the stop is ALLOWED.
    The user still sees every command in the dialog and still needs root
    gate + password. A "changed" file stays blocked (original rule, not
    part of D1: a file that differs from what was approved must be approved
    again first). CONFIRMED by the owner: keep the block for "changed"
    files; if the user does not approve, "Delete without stopping" is
    still available.
D2  Total time for the whole stop: 60 seconds.
D3  No automatic retry. If the stop does not fully succeed, the plugin is
    NOT deleted: the report is shown and the Delete button / dialog opens
    again so the user can try again. The dialog then also offers
    "Delete without stopping" (see Step 4 and 6).
    [CHANGE vs old plan: the old plan always deleted the file even when the
    stop failed. With D3 a failed stop keeps the file, because the plan is
    read from the file and the user must be able to retry.]
D4  Per-command time is not fixed by plugin size (file size does not tell
    how long a command runs). Each command may use whatever is left of the
    60 s total. No 20 s / 40 s rule.
D5  New optional header "// @matchi-boot <path>" (max 5) is ACCEPTED. It is
    used by verify (Step 5) and the same-folder guard (Step 3).
D6  No checkbox and no second question. The delete dialog simply says that
    all the plugin's files and data will be deleted and that what it
    started will be stopped by its uninstall commands. For a plugin that
    declares commands the stop is always sent.
