[FAIL] curl https://example.com without -k: "(60) SSL peer certificate ... not OK" (curl sent alert "unknown CA").
       - date is right (Nov 2026), network is fine (curl -k = 200).
       - curl uses CApath /system/etc/security/cacerts (125 files); CAfile: none.
       - curl with a fresh Mozilla bundle (--cacert) = 200. So the code and network are fine; only the CA lookup fails.
       - Suspected cause (NOT yet proven): Android names the files in cacerts with the old OpenSSL hash,

         missing a root. The test below tells these two apart.

         ship or trust it until its SHA-256 is compared with the one curl.se publishes.
[FAIL] sendat -n 0 -c AT: "no modem AT device found for slot 0" (no stty_lte0 / smd / ttyUSB on this device).
[FAIL] sendat -probe: all 32 /dev/stty_nr0..31 report "no data available" (ENODATA), no port answered.
       - /dev has ttyGS0-7 only besides stty_nr* (ttyGS = USB gadget, not the modem).
       - The probe label "open failed" is misleading: sendOn returns the same error for open, write and read.
         Next code change: say which stage failed.
