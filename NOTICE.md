- UFI-TOOLS-derived source and bundled modem utility notices are retained in `LICENSE-UFI-TOOLS`.
- MatchiTOOL project-specific changes are covered by `LICENSE`.
- NanoHTTPD 2.3.1 is consumed as an external Gradle dependency; consult its upstream distribution for its license and notices.
- No `nfqws` executable is bundled.
- `app/src/main/assets/bin/sendat` is an arm64 executable that the app runs as root. It is built from `tools/sendat/` (stdlib-only Go 1.22.8, `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags "-s -w"`) by `.github/workflows/build-sendat.yml`; it replaces the UPX-packed UFI-TOOLS binary. Not yet tested on the F50 modem: check `sendat -probe` and pin the port in `/data/local/matchitool/sendat.conf` if needed. SHA-256: `dd694216a7199ca07aa5c0a785c802be8957bdb806f001c6785219c81bb2aa10`. `scripts/validate.sh` fails if the file changes, so replace the hash here and there together with any new build.
- `app/src/main/assets/bin/curl` is an arm64 Android executable built from upstream curl source with a statically linked OpenSSL by `.github/workflows/build-binaries.yml` (NDK clang, API 26); it replaces the UFI-TOOLS V4.0.0 binary. It needs only the system libc/libdl/libz, so it only runs on arm64 Android. curl is distributed under the curl license (MIT-style, https://curl.se/docs/copyright.html). The build recipe is the workflow above. SHA-256: `8dda0f1104f17f2e1cd93455f283175df25266792312e32d7a3edc07ad1b43bc`. `scripts/validate.sh` fails if the file changes, so replace the hash here and there together with any new build.
- `jq` is built from upstream jq source by `.github/workflows/build-binaries.yml` (static, arm64). `sha256` and `zreq` were prebuilt arm64 executables taken unchanged from the UFI-TOOLS 4.1.5 APK (`assets/shell/`); both have since been replaced (`sha256` in 1.4.1, `zreq` in 1.4.3, see below), added in 1.4.0 so plugins that call `/data/data/com.minikano.f50_sms/files/NAME` find them (the path is rewritten to this app's files folder). They are copied to the app's files folder at start-up, like curl. `jq` is a statically linked ELF (jq is MIT licensed, https://github.com/jqlang/jq). `sha256` is NOT the UFI-TOOLS binary any more: since 1.4.1 it is a 6-line shell script written for MatchiTOOL (it calls the system `sha256sum` and prints the hash of its argument, or of stdin); the old packed binary had no recorded source. `zreq` is NOT the UFI-TOOLS binary any more: since 1.4.3 it is MatchiTOOL's own Go build (`zreq 1.0 (MatchiTOOL)`, static arm64, module `matchitool/zreq`). It has no built-in router password: sign-in only happens with `-pwd`, `-pwd-file` or the env `ZREQ_PWD`, and the router address must be a private or loopback IPv4. Flags: `-ip`, `-method`, `-params`, `-body`, `-path`, `-json`, `-t`, `-cookie` (env `ZREQ_COOKIE`), `-pwd-mode b64|raw`, `-verbose`, `-version`. A plugin that relied on the old default password must now pass one. SHA-256: jq `738ee0567401f51c8c95c1df118b924d9e97954b00034bb91e37d995faa180e0`, sha256 `c9a941a15741e1f2fa1e183da05a837b08297d89453165d3a7882f481994aa45`, zreq `5fd16c5ba096cea6dfe71e7c6d4821f04584fd4302e147f10ade8844aaa13e8e`. `scripts/validate.sh` fails if any of them changes, so replace the hash here and there together with any new build.
- `ufi_req`, `socat`, `ttyd`, `adb`, `iperf3` and `imei_reader` from UFI-TOOLS are NOT bundled: no plugin in the Phase 0 corpus needs them (the corpus is still empty, so this is a guess to revisit when real plugins are collected).
