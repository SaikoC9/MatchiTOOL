MatchiTOOL - AdGuard Home plugin (latest): what is needed and how to build it
Based on: MatchiTOOL-main 1.4.2 (read here), AdGuard Home release page checked 2026-11-17.
Status: PLAN ONLY. Nothing below was run on an F50 (no arm64 device here). Items marked [VERIFY] must be tested on the device.

======================================================================
1. WHAT "LATEST" IS
======================================================================
- Latest stable AdGuard Home: v0.107.79 (released 18 Aug 2026). Beta v1.0.0-b.x exists; use stable only.
  Source: https://github.com/AdguardTeam/AdGuardHome/releases
- Do NOT hardcode the version. The plugin asks GitHub for the newest tag at install time:
    curl -sL https://api.github.com/repos/AdguardTeam/AdGuardHome/releases/latest | jq -r .tag_name
  (curl and jq are bundled with MatchiTOOL.)
- Asset to download (arm64 Android = linux arm64):
    AdGuardHome_linux_arm64.tar.gz     (fallback: AdGuardHome_linux_armv7.tar.gz)
    checksums.txt                      [VERIFY both names on the release page: only the 386 name was visible to me]
  URL: https://github.com/AdguardTeam/AdGuardHome/releases/download/<tag>/AdGuardHome_linux_arm64.tar.gz
- Config notes from the release notes: v0.107.76 changed YAML durations (supports "d"). Going back to a version
  older than 0.107.76 needs durations converted to hours -> the plugin keeps a backup and never auto-downgrades.

======================================================================
2. WHAT IS NEEDED (list)
======================================================================
A. Device / app (already present in MatchiTOOL 1.4.2)
   1. Root (su) working in MatchiTOOL.                       matchi.hasRoot()
   2. Bundled curl, jq, sha256 (assets/bin).                 matchi.sh.P.curl = /data/local/matchitool/bin/curl
   3. https from curl works (CA bundle fix is in plugin-host-api.js).
   4. Plugin runs TRUSTED (not sandboxed): it needs a dialog, long root jobs, dynamic commands.
      A sandboxed plugin can only run exact fixed shell strings, which does not fit install/update.
   5. github.com / objects.githubusercontent.com: curl runs in the root shell, so the page's network rules do not
      block it. (github.com is on the default list anyway.)

B. Files / folders the plugin creates
   - /data/local/adguardhome/            binary, AdGuardHome.yaml, data/ (stats, querylog, filters), backup/
   - /data/local/adguardhome/agh.sh      helper: start | stop | status | rules-on | rules-off | watch
   - /data/local/matchitool/boot.d/40-adguardhome.sh   boot starter (name must be NN-name.sh so MatchiTOOL can undo it)
   - iptables chains: ADGH_DNS (nat), optional ADGH_DOT (filter)

C. Network design (the important part)
   - The router's dnsmasq already owns port 53 -> AdGuard Home must NOT bind 53.
   - AdGuard Home listens on 5353 (DNS, tcp+udp). Web UI on 3000.
   - iptables NAT redirect, only for traffic coming in from LAN interfaces (br0, plus ap/rndis/usb if present):
        iptables -t nat -N ADGH_DNS
        iptables -t nat -A ADGH_DNS -p udp --dport 53 -j REDIRECT --to-ports 5353
        iptables -t nat -A ADGH_DNS -p tcp --dport 53 -j REDIRECT --to-ports 5353
        iptables -t nat -I PREROUTING -i br0 -j ADGH_DNS
     Same with ip6tables if the device has IPv6 NAT / otherwise block or ignore v6 DNS [VERIFY].
   - Loop safety: rules sit in PREROUTING with -i <lan iface> only. AdGuard Home's own upstream queries are local
     OUTPUT traffic, so they are never redirected back into itself.
   - Find LAN interfaces without "ip -4 route show default": on the F50 that route table is EMPTY even when internet works
     (see MatchiTOOL_Binaries_test_todo.txt). Use: ip route get 8.8.8.8 to find the upstream dev, then pick br0/ap0/rndis0/
     usb0/ecm0 that exist and are not the upstream dev. HostControl.lanFirewallScript in the repo already does this; copy its logic.
   - FAIL-OPEN (must have): if AdGuard Home is not answering on 127.0.0.1:5353, the watchdog removes the redirect so
     clients fall back to dnsmasq. Otherwise a crash = every hotspot client loses DNS.
   - Optional: block DNS-over-TLS (tcp 853) from LAN so clients cannot bypass filtering. Default OFF.

D. AdGuard Home config (AdGuardHome.yaml) - set at first start, not left to the wizard
   - http.address: start on 127.0.0.1:3000 only; after setup switch to 0.0.0.0:3000 (LAN) or keep localhost.
   - dns.port: 5353, dns.bind_hosts: 0.0.0.0 (so redirected LAN traffic is accepted).
   - dns.upstream_dns: e.g. https://dns.quad9.net/dns-query , https://cloudflare-dns.com/dns-query  (user can edit)
   - dns.bootstrap_dns: 9.9.9.9, 1.1.1.1   MANDATORY. Android has no /etc/resolv.conf; Go falls back to 127.0.0.1:53
     (dnsmasq) and DoH host names / filter-list downloads can fail without bootstrap [VERIFY].
   - dns.local_ptr_upstreams: router LAN IP (so client names resolve from dnsmasq).
   - dhcp.enabled: false (never let it fight the router's DHCP).
   - querylog: interval 24h, size_memory small; statistics interval 7d.  Flash and RAM on the F50 are small.
   - filters: only "AdGuard DNS filter" enabled by default. Big lists cost RAM [VERIFY memory on F50].
   - users: admin + bcrypt password (see step 4.5). Never leave the install wizard open on the hotspot.
   - Run with --no-check-update (updates are done by the plugin, not the binary).

D2. Needs from MatchiTOOL's own rules (so the plugin is accepted and can be deleted cleanly)
   - No "curl ... | sh" (scanner blocks it). Download to a file, check sha256, then run it.
   - No rm -rf on /, /data, /sdcard (blocked). rm -rf /data/local/adguardhome is fine.
   - iptables chain must be created with literal text "iptables -t nat -N ADGH_DNS" in a command the host sees,
     otherwise it is not in the ledger and the automatic undo will not know it. Also declare it in @matchi-uninstall.
   - Boot file must be exactly /data/local/matchitool/boot.d/40-adguardhome.sh, root-owned, regular file.
   - Start the process through matchi.root()/matchi.sh.run() so it carries the MATCHI_PLUGIN tag (the delete sweep finds it).
   - Headers must sit in the first 400 lines, one per line, starting with //.

======================================================================
3. PLUGIN HEADERS (put at the top of the file)
======================================================================
// @matchi-name AdGuard Home
// @matchi-version 2.5-matchi
// @matchi-author <you>
// @matchi-description AdGuard Home DNS ad blocker for the hotspot (installs the latest stable arm64 build).
// @matchi-requires root, curl, jq
// @matchi-data /data/local/adguardhome
// @matchi-uninstall rm -f /data/local/matchitool/boot.d/40-adguardhome.sh
// @matchi-uninstall [ ! -f /data/local/adguardhome/agh.sh ] || sh /data/local/adguardhome/agh.sh stop
// @matchi-uninstall while iptables -t nat -D PREROUTING -j ADGH_DNS 2>/dev/null; do :; done; iptables -t nat -F ADGH_DNS 2>/dev/null; iptables -t nat -X ADGH_DNS 2>/dev/null; true
// @matchi-uninstall rm -rf /data/local/adguardhome
// @matchi-check ! ps -A -o ARGS 2>/dev/null | grep -v grep | grep -q 'adguardhome/AdGuardHome' && ! iptables -t nat -S 2>/dev/null | grep -q ADGH_DNS && [ ! -e /data/local/adguardhome ]
// @matchi-boot /data/local/matchitool/boot.d/40-adguardhome.sh
Notes: each uninstall line max 300 chars, max 10 lines. The PREROUTING jump uses "-i br0 -j ADGH_DNS" in practice; if you add one
jump per interface, delete them in a loop by matching "-j ADGH_DNS" from "iptables -t nat -S PREROUTING" (MatchiTOOL's own undo
does this by number). Boot entry is removed FIRST, then the process is stopped, so a reboot in between cannot restart it.

4. HOW TO IMPLEMENT (steps)
======================================================================
Step 1 - Skeleton
   - One file: AdGuardHome_MatchiTOOL.js. Trusted plugin, uses only window.matchi.* (matchi.root, matchi.sh, matchi.modal,
     matchi.toast, matchi.menu, matchi.switch, matchi.loading, matchi.router).  Do not use page-only helpers.
   - Add a button in matchi.menu() ("AdGuard Home") that opens a modal. Modal shows: installed version, latest version,
     running yes/no, DNS redirect on/off, LAN web UI link (http://<matchi.sh.lanIp()>:3000), buttons:
     Install/Update, Start, Stop, Redirect on/off, Open UI, Refresh status, Uninstall data.
   - The modal footer (Refresh / Close) works with createModal as shipped in 1.4.1.

Step 2 - Preflight check (read-only)
   - matchi.hasRoot(); uname -m == aarch64 (else armv7 asset); free space on /data (need ~80 MB: tar + binary + data);
     ports 5353 and 3000 free (use "netstat -tuln" or read /proc/net/{tcp,udp}); iptables present; tar present (toybox tar -xzf).
   - Detect an old AdGuard Home from the UFI-TOOLS plugin (running process named AdGuardHome, or a folder such as
     /data/adguardhome). Offer: stop it first / reuse its yaml. The MatchiTOOL "two plugins, one folder" guard protects shared paths.

Step 3 - Download + verify + install (long job, uses matchi.sh.run with timeout > 110 s so it runs as a background job)
   a. tag=$(curl -sL https://api.github.com/repos/AdguardTeam/AdGuardHome/releases/latest | jq -r .tag_name)
   b. mkdir -p /data/local/adguardhome/dl; curl -L --retry 3 -o dl/agh.tgz  .../download/$tag/AdGuardHome_linux_arm64.tar.gz
   c. curl -L -o dl/checksums.txt .../checksums.txt ; compare: sha256 dl/agh.tgz  against the line for that file name.
      MISMATCH = stop, delete the download, show an error. (A file downloaded without verifying must never be run as root.)
   d. tar -xzf dl/agh.tgz -C dl  -> dl/AdGuardHome/AdGuardHome ; move to /data/local/adguardhome/AdGuardHome ; chmod 755
   e. Run "AdGuardHome --version" and show the output. Delete dl/.
   f. Offline path: matchi.sh.upload(file) to /data/local/matchitool/uploads then install from it (already supported by the helper).
   Update = same steps, but first: stop service, cp binary and yaml into backup/<oldversion>/, then swap, then start.
   If the new binary fails to start: automatically put the old binary back.

Step 4 - First configuration (no open wizard)
   1. Write a minimal AdGuardHome.yaml (http 127.0.0.1:3000, dns port 5353, bootstrap, upstreams, querylog/stats limits).
   2. Start AdGuard Home (step 5).
   3. Wait for http://127.0.0.1:3000/control/status (curl, up to ~20 s).
   4. If still in install mode, POST to /control/install/configure with web.ip/port, dns.ip/port 5353, username, password.
   5. Password: ask the person in the modal (matchi.form) or generate a random one and show it once. Send it to AGH only over
      127.0.0.1. Do NOT save it in the plugin's localStorage or the log. [bcrypt is done by AGH itself through the API,
      so the plugin needs no bcrypt tool.]
   6. Optionally move http bind to 0.0.0.0:3000 so the hotspot clients' admin can open it. Default: LAN allowed only after a password exists.

Step 5 - Run it (helper script agh.sh written by the plugin with a quoted heredoc, like Stop_Example.js)
   start:  [ -f pid ] && kill -0 $(cat pid) 2>/dev/null && exit 0
           nohup /data/local/adguardhome/AdGuardHome -w /data/local/adguardhome -c /data/local/adguardhome/AdGuardHome.yaml \
             --no-check-update >/data/local/adguardhome/agh.log 2>&1 & echo $! > pid
   stop:   rules-off first, then kill the pid (SIGTERM, wait 3 s, SIGKILL), rm pid.  Safe to run twice.
   status: running? pid; answers on 127.0.0.1:5353 (nslookup/curl DoH-less test: "nslookup example.com 127.0.0.1 -port=5353" or
           use AGH's own http://127.0.0.1:3000/control/status);  rules present?
   rules-on / rules-off: build and remove the ADGH_DNS chain exactly as in section 2C. Use "iptables -w 5" to wait for the xtables lock.
   watch:  loop every 20-30 s: if AGH is dead -> restart it (max 3 times, then give up) and rules-off (fail-open);
           if AGH is healthy and "redirect enabled" flag exists -> make sure rules are present (netd/tethering can rebuild chains
           after a hotspot restart or data reconnect). Keep the watchdog light: the F50 already pays for ttl.sh-like loops.

Step 6 - Boot persistence
   Write /data/local/matchitool/boot.d/40-adguardhome.sh (root-owned, 0700 or 0755 not group/other-writable):
       sh /data/local/adguardhome/agh.sh boot >/dev/null 2>&1 &
   boot = wait until br0 exists and has an IP (poll up to ~60 s), then start, then watch.
   MatchiTOOL only runs boot scripts that are real root-owned files in a root-owned, non-writable folder (HostService.kt).
   Respect a plugin switch file (/data/local/adguardhome/autostart): if the user turned auto-start off, the boot script exits.

Step 7 - Status / UI polish
   - Periodic refresh only while the modal is open (matchi.interval), 5-10 s. Do not poll in the background.
   - Show blocked today / queries today read from http://127.0.0.1:3000/control/stats with curl + jq (needs the saved login,
     use curl -u user:pass from a root-only file /data/local/adguardhome/.auth, mode 600) [VERIFY it is acceptable to store; alternative: do not show stats].
   - Show the last 20 lines of agh.log on error.
   - Strings: English first; MatchiTOOL has i18n.js if you want zh/other later.

Step 8 - Uninstall behaviour
   - Headers in section 3 make "Delete and stop" work: boot file, process, firewall chain, data folder, then the check.
   - Because the plugin also writes the chain through agh.sh (a helper script), the host ledger may not see it -> the
     explicit @matchi-uninstall line for ADGH_DNS is REQUIRED, not optional.
   - Test that after delete: ps shows no AdGuardHome, iptables -t nat -S has no ADGH_DNS, folder gone, hotspot DNS still works.

5. KNOWN RISKS / UNKNOWNS (decide before coding)
======================================================================
 1. SELinux on the F50: a binary in /data/local may be denied binding or networking under some su contexts. [VERIFY by running it]
 2. Go DNS on Android without /etc/resolv.conf: bootstrap_dns must be set (see 2D). [VERIFY]
 3. IPv6 clients: REDIRECT only covers IPv4 unless ip6tables nat works on this kernel. Otherwise some clients keep using
    the router's v6 DNS and skip filtering. Decide: accept / block v6 DNS / hand out v4 DNS only. [VERIFY]
 4. RAM/flash: query log and big filter lists. Keep defaults small. [VERIFY free memory with AGH running]
 5. Clients using DoH/DoT/their own DNS (Chrome secure DNS, Private DNS on Android) bypass any DNS blocker. Redirect catches
    plain port 53 only; DoT (853) can be blocked optionally; DoH cannot be blocked this way.
 6. Hotspot restart / SIM reconnect may rebuild iptables chains: the watchdog re-checks rules.
 7. Exposing the web UI to every hotspot client: require a password; default to localhost until it is set.
 8. Asset names (arm64 tar.gz, checksums.txt) and the checksum line format must be confirmed on the release page.
 9. Update from an old UFI-TOOLS AdGuard install: config version may differ; plugin must back up yaml before touching it.
10. Not tested on a device: treat the first run like the other "Not yet tried on a device" items in this repo.

6. TEST PLAN (on the F50, in this order)
======================================================================
 T1 preflight: root yes, aarch64, space ok, ports free.
 T2 download: tag found, sha256 matches checksums.txt, "AdGuardHome --version" prints v0.107.79 (or newer).
 T3 start: process alive, 127.0.0.1:3000 answers, DNS answers on 5353:  nslookup example.com 127.0.0.1 -port=5353.
 T4 redirect ON: from a phone on the hotspot: nslookup doubleclick.net -> blocked answer (0.0.0.0); example.com resolves.
 T5 kill -9 AdGuardHome: within ~30 s the watchdog restarts it, or removes the redirect; phone DNS never stays dead.
 T6 reboot router: boot script starts AGH, rules come back after br0 is up.
 T7 hotspot off/on and mobile data off/on: rules still present after (or re-added by the watchdog).
 T8 update: simulate an older version, update, confirm backup folder, and rollback when the new binary is a bad file.
 T9 Delete and stop: dialog lists the process, chain, boot script; afterwards ps / iptables / folder are clean; DNS still works.
10 Re-install after delete works from scratch.
