MatchiTOOL - UFI-TOOLS style AT & Radio: build plan (phases)
=============================================================

GOAL
----
Bring the radio controls of UFI-TOOLS into MatchiTOOL's AT & Radio tool:
network mode, band lock, cell lock, performance mode and more AT quick
buttons, without breaking the signal on the F50.

WHAT WAS FOUND (from the MatchiTOOL zip and the UFI-TOOLS 4.1.5 APK)
---------------------------------------------------------------------
Already in MatchiTOOL (app/src/main/assets/plugins/AT_Radio.js, also embedded
in assets/web/index.html around line 723, "AT_Radio.js"):
  - AT console with SIM slot picker (this is the slot for AT commands only)
  - presets: CSQ, COPS, CEREG, IMEI, CCID, ATI
  - VoLTE switch (AT+CAVIMS) and VoNR switch (AT+SP5GCMDS ... 45)
  - NR supported band list (AT+SP5GCMDS="get nr support_band")
  This is the same AT set UFI's own native code uses. Nothing more is missing
  on the pure AT side except the extra quick buttons below.

In UFI-TOOLS but NOT in MatchiTOOL (all through the router goform API, not AT):
  - Network mode          SET_BEARER_PREFERENCE   (values seen: Only_LTE,
                          LTE_AND_5G, WL_AND_5G, Only_5G; read key: net_select)
  - LTE band lock         LTE_BAND_LOCK           (read key: lte_band_lock)
  - NR band lock          NR_BAND_LOCK            (read key: nr_band_lock)
  - Cell lock / unlock    CELL_LOCK, UNLOCK_ALL_CELL
  - Performance mode      PERFORMANCE_MODE_SETTING (key: performance_mode)
  - AT quick buttons      IMSI, QoS (AT+CGEQOSRDP=1), modem reboot
                          (AT+SFUN=4 then AT+SFUN=5), modem info
  - APN profiles          (apn_* keys)

NOT PLANNED
  - SIM slot switch (SET_SIM_SLOT) - removed from this plan on request.
    The existing "SIM slot" picker in the AT console stays as it is.

HOW IT CAN BE BUILT
-------------------
MatchiTOOL already has a generic router proxy: POST /api/zte (and
/api/goform/...). It logs in, adds the AD token for set calls and serialises
router calls. So no new Kotlin is needed for phases 1-3: build in
AT_Radio.js (and the embedded copy in index.html).

WHAT IS NOT CONFIRMED (read this first)
---------------------------------------
UFI's main.js is heavily obfuscated. The command names above were recovered,
but NOT the exact parameter names and value formats of LTE_BAND_LOCK,
NR_BAND_LOCK and CELL_LOCK (how bands are joined, how a cell is described).
Do not guess these. Phase 2 starts by capturing the real format on the F50.

RULES FOR EVERY PHASE
---------------------
  1. One phase at a time. Test on the phone before the next one.
  2. Edit app/src/main/assets/plugins/AT_Radio.js, then update the embedded
     copy in app/src/main/assets/web/index.html (script "AT_Radio.js"). If you
     touch a "@include web-src/..." block, edit app/src/main/web-src/ and run:
         node scripts/build-web.js
  3. Run:  bash scripts/validate.sh   (must pass before every commit).
  4. Every write (set) needs a confirm dialog that names the change.
  5. Always READ and show the current value first, and keep a way back
     (Auto / Unlock all) one tap away.
  6. Do not poll the radio settings in the background. Read them when the
     tool window opens and after each change only.
  7. Pause the Live Status loops while this window is open (otherOpen()).

PHASE 0 - Capture the real formats (no behaviour change)
--------------------------------------------------------
Work
  - On the F50, open the router's own page, change nothing, and use the
    browser dev tools (Network tab) to note the goform GET keys that hold:
    net_select, lte_band_lock, nr_band_lock, performance_mode, locked cell
    info and the neighbour cell list. Save the raw JSON.
  - Using the router page itself, set one harmless value of each kind
    (for example network mode to Auto, then back) and copy the exact
    POST body the page sends: goformId + parameter names + value format.
  - Write it all in docs/AT_RADIO_FORMATS.md (new file).
Done when
  - docs/AT_RADIO_FORMATS.md lists, for each command: goformId, parameter
    names, example values, and the read key that confirms the change.

PHASE 1 - Safe additions
------------------------
Work
  - New quick buttons: IMSI (AT+CIMI), QoS (AT+CGEQOSRDP=1), Modem info.
  - Modem reboot button (AT+SFUN=4 then AT+SFUN=5) with a confirm dialog
    ("Signal will drop for about 30 s").
  - Network mode dropdown: Auto 5G/4G/3G, 5G NSA, 5G SA, 4G only.
    Read net_select first and select the current one. On change: confirm,
    send SET_BEARER_PREFERENCE through /api/zte, re-read net_select and show
    the result.
  - Performance mode switch: read performance_mode, send
    PERFORMANCE_MODE_SETTING on change, re-read.
  - Hide any control whose read key comes back empty on this firmware.
Done when
  - Each control shows the real current value on open, changes it, and the
    re-read value matches. "Auto" brings the phone back to normal.

PHASE 2 - Band lock (LTE and NR)
--------------------------------
Needs docs/AT_RADIO_FORMATS.md from Phase 0.
Work
  - Show the bands as tick boxes: LTE list and NR list (NR list can start
    from the existing AT+SP5GCMDS support_band result).
  - Read lte_band_lock / nr_band_lock first and tick what is locked now.
  - "Lock bands" sends LTE_BAND_LOCK / NR_BAND_LOCK in the confirmed format.
    "Unlock bands" restores all bands (Auto). Confirm dialog lists the bands.
  - Refuse to lock with zero bands ticked.
  - UFI's note: no reboot needed, switch network mode afterwards to apply.
Done when
  - Locking one band, then reading the band in Live Status, shows that band.
    Unlock returns to the original list.

PHASE 3 - Cell lock (highest risk, do last)
-------------------------------------------
Work
  - Show the current cell and the neighbour cell list (read-only first).
  - Lock a chosen cell with CELL_LOCK in the confirmed format; "Unlock all
    cells" sends UNLOCK_ALL_CELL.
  - Strong warning text (from UFI: a wrong cell can give no or unstable
    signal). Unlock button always visible.
  - Optional: auto-unlock if there is no registration after 60 s.
Done when
  - Lock and unlock both work on the F50 and the phone registers again after
    unlock without a reboot.

PHASE 4 - Tests, release, on-device check
-----------------------------------------
Work
  - Add a node test under scripts/ (same style as scripts/test_log_basket.js)
    for the value parsing and the command building (no real router).
  - Run: node scripts/build-web.js --check ; bash scripts/validate.sh
  - Update CHANGELOG.md. If the version changes, change ALL of these
    together: app/build.gradle.kts (versionCode, versionName), PAGE_VERSION in
    index.html, scripts/validate.sh (3 version checks and the final message),
    README.md.
  - On the phone: test every control once, then confirm the SMS tool and
    Live Status still work and the phone is not hotter than before.
Done when
  - validate.sh passes, every control has been tested on the F50, and
    "Auto" / "Unlock" restores the original radio state.

RISKS AND HOW TO HANDLE THEM
----------------------------
  - Wrong band or cell lock can leave the phone with no signal: always read
    first, confirm before write, keep Auto / Unlock one tap away.
  - Unknown parameter formats: Phase 0 must be done before Phase 2 and 3.
  - Router login cool-down: only call the router on user action, never in a
    loop; a failing call must not retry in a tight loop.
  - Firmware differences: a key that comes back empty means "hide the
    control", never "show 0".
  - Router session: calls are serialised, so a long radio change can delay
    SMS actions; keep the Live Status loops paused while this window is open.
